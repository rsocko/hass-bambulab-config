Print Queue · Kanban view (mockup)

Adds a Kanban board mode to the existing unified queue card. State filter chips drive which columns are visible; the same chips also control which state groups appear in the list view. Cards carry a subtle state-tinted wash so they remain visually grouped even when scrolled or rearranged. The hero "Time Remaining" tile excludes plates already marked done.

Mockup intent / wiring notes

  • State palette is exposed as CSS custom properties (--state-backlog … --state-done) and applied to each card via a --state override. The same variables drive the list view's group header, the kanban column header, and the small filter swatches — one source of truth. No per-card state pill is needed: the color wash + the column (or list group) it sits in already convey the state.
  • View switch is a 2-way toggle stored in localStorage (key uq-view-${printer_id}). Default = List for users who upgrade in place; Kanban is opt-in.
  • Filters are dropdowns (not chips) for consistency across views: a multi-select States dropdown hides entries from the list and hides entire columns from the kanban (default visible = all six states, matching QUEUE_DEFAULT_VISIBLE_STATES), and a single-select Source dropdown (All / Catalog / Working Files / Ideas) narrows entries to one source kind across both views.
  • Kanban scroll: only the columns container scrolls horizontally (GitHub Projects style, fixed 300px columns). Individual columns never scroll vertically — they grow with their contents, and the page absorbs overflow if a single column gets very tall.
  • List view sort: when sorted by Rank, entries render as one flat ranked list and dragging a card reorders it (calls POST /api/v1/queue/reorder). When sorted by Duration or Recently added, drag handles disappear because the ordering is computed from a field, not manual rank. State grouping is dropped in the list view; the state color wash on each card preserves visual grouping without forcing structural grouping.
  • Drag & drop in kanban moves an entry between columns and would call PATCH /api/v1/queue/{id} with the new state. Transitions are validated against QUEUE_STATE_TRANSITIONS already in the card source — invalid drops snap back and toast a reason.
  • Time remaining (hero): sum of plate.estimated_minutes for plates whose state !== 'done', plus the live sensor.bambulab_p1s_remaining_time for the currently-printing plate. Each card shows the same calc per-job (4h 12m left of 7h 30m) so it's obvious which plates are skipped.

# Skip Objects Feature — Research, Analysis & Implementation Guide

## Overview

This document explains exactly how the **Skip Objects** feature works in the
[ha-bambulab-cards](https://github.com/greghesp/ha-bambulab-cards) Printer Control Card,
what entities and services are involved from the
[ha-bambulab](https://github.com/greghesp/ha-bambulab) integration, and how to replicate
or extend the functionality with custom YAML cards and HA scripts in this repository.

---

## 1. Background: What Is Object Skipping?

Bambu Lab printers can print multiple objects (parts) on the build plate in a single job.
If one object fails mid-print (spaghetti, poor adhesion, etc.) the printer can **skip that
object** for the remainder of the print, continuing with the remaining objects normally.
This avoids wasting filament on a failed piece while saving the rest of the job.

The skip command is sent to the printer over MQTT and is only valid while a print is actively
running.

---

## 2. The Entities Provided by ha-bambulab

The integration exposes three entities per printer that are required for Skip Objects:

### `sensor.{prefix}_printable_objects`

| Property | Details |
|----------|---------|
| **State** | Count of printable objects (integer) |
| **Attribute: `objects`** | Dict of `{id: name}` — e.g. `{"1": "Lid", "3": "Base"}` |
| **Icon** | `mdi:cube-unfolded` |
| **Notes** | IDs are integer keys; values are the Bambu Studio object names |

This sensor is updated when a new print starts and the printer reports its object list.

### `sensor.{prefix}_skipped_objects`

| Property | Details |
|----------|---------|
| **State** | Count of already-skipped objects |
| **Attribute: `objects`** | List of integer IDs already skipped — e.g. `[1]` |
| **Notes** | Updated by the printer over MQTT whenever objects are skipped |

### `image.{prefix}_pick_image`

| Property | Details |
|----------|---------|
| **State** | ISO 8601 timestamp of last image update |
| **`entity_picture`** | URL path to the PNG image |
| **Content type** | `image/png` |
| **Size** | 512 × 512 pixels |

The **pick image** is a special PNG generated by Bambu Studio and stored in the print file.
Each printable object occupies a region of pixels with a **unique solid RGB color** — a
colormap. The background (no object) is transparent. This is what allows the custom card to
do click-to-select: it maps any pixel's RGB value to an object ID.

> **Key insight:** The pixel color in the pick image _is_ the object identifier.
> The RGB integer `r | (g << 8) | (b << 16)` for a pixel equals the numeric object ID key
> stored in `printable_objects.attributes.objects`.

## 3. The Service: `bambu_lab.skip_objects`

The integration provides the `bambu_lab.skip_objects` service. It translates a list of
integer object IDs into an MQTT `skip_objects` command sent directly to the printer.

**Service call format:**
```yaml
service: bambu_lab.skip_objects
data:
  device_id: "YOUR_PRINTER_DEVICE_ID"   # HA device ID (not entity_id)
  objects: "1,3"                         # Comma-separated integer IDs to skip
```

The `objects` field accepts:
- A comma-separated string: `"1,3,5"`
- A single integer: `1`
- A list: `[1, 3, 5]`

**Critical behaviour:** The printer **replaces** its skip list with whatever you send.
It does **not** add incrementally. To skip Object 2 when Object 1 is already skipped,
you must call the service with `objects: "1,2"` (both IDs). Sending only `objects: "2"`
would un-skip Object 1.

**The underlying MQTT command sent to the printer:**
```json
{
  "print": {
    "sequence_id": "0",
    "command": "skip_objects",
    "obj_list": [1, 2]
  }
}
```

## 4. How the Custom Card (`ha-bambulab-cards`) Implements Skip Objects

### 4.1 Overall Flow

```
User opens card → card shows speed profile + pause/play/stop buttons
                                        ↓
                 "Skip Objects" button (mdi:debug-step-over) appears
                 ONLY when all these conditions are true:
                  • printable_objects count is between 2 and 64
                  • pick_image entity has a valid state (not undefined)
                  • stop button is available (printer is printing)
```

### 4.2 The Popup Modal

Clicking the Skip button opens a popup overlay containing:
1. **A canvas element** overlaid on a build plate SVG background
2. **A scrollable checkbox list** of all printable object names

### 4.3 Canvas-Based Interactive Image

The card uses two `<canvas>` elements:

| Canvas | Purpose |
|--------|---------|
| **Hidden canvas** | Stores the raw pick image pixels — used for color lookups |
| **Visible canvas** | Displays the colorized version — shown to the user |

**How colorization works (each render frame):**
1. Read the pick image from HA (`image.pick_image.attributes.entity_picture`)
2. Draw it to the hidden canvas via `drawImage()`
3. Read all 512×512 pixels from the hidden canvas into a data buffer
4. For each non-transparent pixel, map its RGB value to an object ID:
   - `id = r | (g << 8) | (b << 16)` (with alpha forced to 0 for comparisons)
5. Colorize the visible canvas:
   - **Green** (`rgb(0,255,0)`) — object is printable and _not_ selected for skipping
   - **Red** (`rgb(255,0,0)`) — object is _selected_ to be skipped in this session
   - **Blue** (`rgb(0,0,255)`) — 2-pixel border on the currently hovered object
6. Write the modified pixel data back to the visible canvas

### 4.4 Click Detection on the Canvas

When the user clicks on the visible canvas:
1. Translate the click position from CSS coordinates to native 512×512 canvas coordinates
   (using `offsetWidth / canvas.width` scale factors)
2. Read the pixel at that position from the **hidden canvas** (raw pick image, not colorized)
3. Convert the pixel to an integer key: `r | (g << 8) | (b << 16)` with alpha = 0
4. If `key != 0` (not background) and the object is not already permanently skipped:
   toggle its `to_skip` state

### 4.5 Object State Model

Each object has three fields:

| Field | Type | Meaning |
|-------|------|---------|
| `name` | string | Display name from `printable_objects.attributes.objects` |
| `skipped` | boolean | Already permanently skipped (reported by printer) |
| `to_skip` | boolean | Selected in the current popup session |

- Already-skipped objects are shown checked and disabled (greyed out) — they cannot be un-skipped from the card
- `to_skip` is initialised to match `skipped` when the popup opens
- Cancelling the popup resets `to_skip` back to match `skipped`

### 4.6 Committing the Skip

When the user clicks the "Skip" button in the popup:
```typescript
const list = Array.from(objects.keys())
  .filter(key => objects.get(key)!.to_skip)
  .join(",");

hass.callService("bambu_lab", "skip_objects", {
  device_id: this._device_id,
  objects: list
});
```

The button is disabled unless at least one object with `to_skip = true` and `skipped = false` exists.

### 4.7 Auto-refresh

The card watches for state changes on both `pick_image` and `skipped_objects`. When either
changes (new print, or printer confirms a skip), the canvas is re-initialized and the
checkbox list is rebuilt from fresh data.

## 5. Why This Feature Is Not Available in the ha-bambulab Integration Alone

The `ha-bambulab` integration provides:
- The `bambu_lab.skip_objects` **service** ✓
- The `printable_objects` and `skipped_objects` **sensor entities** ✓
- The `pick_image` **image entity** ✓

What the integration does **not** provide:
- Any default Lovelace card or button for triggering the skip
- The canvas-rendering colormap logic (this lives entirely in the custom JS card)
- State management for the "pending skip" session (also in the custom card)

The interactive pick-image UI requires JavaScript running in the browser — it cannot be
replicated with standard Lovelace YAML alone. However, the **service call** itself can be
triggered from YAML cards, automations, and scripts.

## 6. Replication Options Without the Custom Card

### Option A — Developer Tools (Manual Use)

For occasional use, call the service from HA Developer Tools → Services:
```yaml
service: bambu_lab.skip_objects
data:
  device_id: "YOUR_DEVICE_ID"
  objects: "1,2"
```

Find your device ID in Settings → Devices & Services → Devices → your printer.

### Option B — HA Script (Automation-Friendly)

See [`homeassistant/packages/3d_printing/printer_controls/scripts/skip_objects_script.yaml`](/homeassistant/packages/3d_printing/printer_controls/scripts/skip_objects_script.yaml) for a
reusable script that:
- Takes an `object_id` parameter
- Reads the current `skipped_objects` to preserve already-skipped items
- Calls `bambu_lab.skip_objects` with the combined list

This is the recommended approach for automation-triggered skipping (e.g. skip object when
spaghetti detection fires).

### Option C — Dashboard Informational Card

See [`homeassistant/packages/3d_printing/printer_controls/dashboard_cards/skip-objects-card.yaml`](/homeassistant/packages/3d_printing/printer_controls/dashboard_cards/skip-objects-card.yaml) for a `custom:button-card` implementation that:
- Displays each printable object with its current skip status
- Shows a "Skip" button per object (calls the skip service, preserving existing skips)
- Only shows when Skip Objects is active (2–64 objects, print is running)

> **Limitation:** Each click is a one-way action (skip, no undo). For full interactive
> selection and confirm-before-commit workflow, use the `ha-bambulab-cards` custom card.

### Option D — Full Custom Card (Recommended for UI)

Install `ha-bambulab-cards` via HACS. The `ha-bambulab-print_control-card` provides the
complete canvas-based interactive object selection UI. This is the lowest-effort path to the
full visual experience.

## 8. Conditions for Skip Objects to Be Available

All of these must be true before Skip Objects is functional:

1. `sensor.{prefix}_printable_objects` state is between `2` and `64` (inclusive)
2. `image.{prefix}_pick_image` state is not `undefined` / `unknown` (image has loaded)
3. `button.{prefix}_stop_print` is **not** `unavailable` (printer is actively printing)

These conditions match the `isSkipButtonEnabled()` helper in the custom card.

MakerWorld URL Import Popup

Popup-based child wizard aligned to issue #1630. The mockup keeps the primary Intake wizard's shell, stepper, validation language, and commit semantics, but swaps the file-picker Source step for a MakerWorld-specific URL resolve and review flow. It also treats Working Files as a first-class destination per issue #1627.

The refined flow is metadata-first: supported MakerWorld URLs attempt authenticated metadata capture automatically, then let the operator continue with metadata-only publish or full download. Link Only remains in the data model, but only appears as a degraded fallback when auth or API resolution fails.

What will happen

  • Pressing `Next` here only advances to Commit.
  • The selected 3MF may already be present in temporary staging for validation, but it is not finalized yet.
  • If deferred, Queue Review remains the next authoritative decision point.
  • If destination is Working Files, only linkage metadata is written into `.modelmeta.json`; the full MakerWorld snapshot remains in intake audit storage.
  • If the operator continued as Link Only after capture failure, this screen becomes a provenance-only confirmation instead of a download-or-publish checkpoint.
This screen is intentionally separated from Step 3 so the five-step flow remains honest: target choice first, validation second, commit third. Temporary staging for duplicate analysis may exist here, but final outputs are not created until the Commit-step action is pressed.

Model Catalog · Toolbar / header redesign

Implements the toolbar/header changes called out in #1216: sort moves into the title row; page controls move between the filter bar and the grid and are centered; prev/next become icon buttons; Models / Page, total count, view variant, Show / Hide media, refresh, favorite, and Other Files all live on the strip. Two layout options are presented below; this mockup is the toolbar shell only — card grid is sketched as skeleton placeholders.

Option A — Recommended PRIMARY

Three stacked rows with progressive visual weight: title (with inline sort and Import menu) → filter bar (text/select filters + favorites/other-files quick chips) → centered page-control strip. The strip groups navigation (prev/next icons + page indicator + count) on the left, density (Models/Page, View variant) in the middle, and display toggles (Show media, Refresh) on the right; whole strip is centered as a unit. Mirror strip below the grid uses the same DOM but hides the toggle group on small viewports.

Option A · notes

  • Sort lives in the title row as an accented inline pill (matching the print-history sort placement). Keeping it out of the page strip keeps the strip purely about navigation + density + display.
  • Import menu lives in the title row and is always visible on Catalog. Menu actions are `Browser Upload` and `Server Inbox`, each jumping into the shared intake wizard flow with mode preselected.
  • Page strip is a single centered row on desktop. On small viewports each .group wraps to its own line but stays centered (uses flex-wrap, no JS).
  • Prev/next icons use chevrons (i-prev/i-next) and double-chevrons for first/last, mirroring the print-history toolbar grammar (mdi:page-first, mdi:chevron-left, etc.).
  • Total count is part of the page indicator (1 / 5 · 47 models) so it doesn't compete with the title-row metadata. Accent color draws the eye to the live count.
  • Models / page is a select rather than a slider; the print-history slider works because it's runtime-tunable, but the catalog is closer to the AppDaemon list-view ergonomics where discrete steps (12/24/48/96) read better.
  • View variant (Compact / Media / List) becomes a dropdown per #1216 ("Drop down for Card"), replacing the current 3 toggle buttons. Saves ~80 px of horizontal real estate and keeps focus on the high-frequency controls (page nav).
  • Show / Hide media is a single aria-pressed eye toggle. When pressed, the card grid renders the no-media variant of each card (text-only), matching input_boolean.print_history_show_images.
  • Refresh spins on press and clears when the underlying refresh resolves; keeps consistency with the print-history toolbar refresh affordance.
  • Favorite filter is the always-visible amber pill on the filter bar (top-level favorites only), and a per-card star action lives on each card surface (already in the compact mockup). The two are deliberately separate concerns.
  • Other Files appears as a top-level filter chip ("Has other files") and as per-card chips (PDF/IMG/Docs counts already in the compact mockup). The chip filter scopes the grid; the per-card chips advertise what's inside.
  • Bottom mirror repeats only navigation + page-size, not the toggle group, because that group sets persistent display state and only needs one entry point.

Option B — Two-row header ALT · ~30% less vertical chrome

Collapses Option A's title row + page-control strip into a single full-width header bar, leaving just two rows above the grid: (1) header (title + sort + page nav + density + display toggles) and (2) filter bar (search + selects + favorites/other-files chips). Saves roughly one row (~52 px at default density) compared to Option A.

Vertical comparison — Option A: title (54 px) + filter (50 px) + page strip (54 px) = ~158 px above grid. Option B: header (52 px) + filter (50 px) = ~102 px above grid. Option C: combined (66 px) = ~66 px above grid.

Option B · trade-offs

  • + Genuinely ~52 px shorter than Option A — one entire row is removed by merging title/sort with page nav and density.
  • + The header reads left-to-right as identity → location in result set → controls, so navigation feels primary.
  • + Sort, View, and Per-page all become labelled selects ("Sort: Recent", "View: Compact", "24 / page") so the row is self-describing without inline labels eating space.
  • − Page nav is no longer centered; it's pinned to the left of the trailing controls. If the issue specifically wants the nav visually centered, Option A is the better fit.
  • − Header wraps to two lines below ~960 px viewport (filter bar then becomes row 3), so on narrow tablets the savings vanish.
  • Recommended if vertical density matters more than centered-nav symmetry with print-history.

Option C — Single-row, filters in popover EXPERIMENTAL · ~60% less chrome

Most aggressive variant. One row above the grid: title + page nav + every control. Search becomes an inline input that expands on focus; the rest of the filter selects (collection / creator / tag / queue) collapse behind a single Filters button that opens a popover. Active filter count appears as a badge on the button so users can see at a glance how scoped the result set is.

Option C · trade-offs

  • + ~66 px above the grid — less than half of Option A. Best vertical real estate for the card grid itself.
  • + Active-filter badge (3) gives immediate feedback that the result set is scoped, which Options A/B don't visually convey.
  • + Reads cleanly on tablets; scales down to ~720 px before the Filters button needs to absorb sort/view/per-page too.
  • − Filters are hidden until you click. Lower discoverability for users who don't expect a popover; a regression for power-users who want all filters visible at once.
  • − Diverges further from print-history's pattern; less code/style sharing between the two browsers.
  • − Popover positioning + focus-trap behavior is non-trivial; needs a keyboard-accessible close affordance and ESC handling.
  • Recommended if the dashboard is mounted on a small wall display or if the card grid is the dominant scan surface.

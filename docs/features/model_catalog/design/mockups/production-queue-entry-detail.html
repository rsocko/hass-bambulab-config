Design rationale

Why one popup instead of separate edit modal + detail drawer The old split required two different user gestures ("Edit" vs "View Details") to see related information, and both surfaces needed to stay in sync. A single popup eliminates that confusion, and the tabbed layout keeps the UI compact without hiding anything.
Fixing the re-render flash The flash happens because _loadQueueData() calls _render(), which replaces shadowRoot.innerHTML entirely — including the open modal. The fix is to skip the full re-render while any modal is open and re-render once after the data refresh completes. Modal state (title edits, tab position) is preserved in component properties, so nothing is lost.
Plate "Mark done" vs automatic archive linkage Automatic completion fires on high-confidence archive linkage. The manual "Mark done" button is the operator override for cases where confidence is low or the archive was never linked. Unchecking a plate de-selects it from future prints of this entry but does not retroactively affect completion count.
State dropdown in the titlebar Moving state change into the titlebar means the operator can change state without navigating away or hunting for a separate button. The dropdown is constrained to valid transitions from the backend — invalid transitions are either hidden or shown disabled (TBD based on how many valid states exist from any given current state).
Idea variant is narrower and simpler Ideas have no files or plates, so the "Files & Plates" tab is omitted entirely. Instead, the footer offers a "Promote to Working Group" affordance — the first step toward an idea becoming a printable entry. This keeps the idea entry lightweight without pretending it has structure it does not.
Popup vs drawer decision The old drawer competed visually with the full-width queue board behind it. A centered popup with a dimmed backdrop (matching the Add flow) is more consistent with patterns used elsewhere in the dashboard family, reduces cognitive load, and does not require managing drawer width relative to the card's panel layout.

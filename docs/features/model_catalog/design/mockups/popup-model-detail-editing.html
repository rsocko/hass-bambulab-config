Design rationale. Two variants shown because the user selected "Show both options".

Variant A (Hybrid Inline): Tags, collections, and projects are always interactive — no mode toggle needed for membership changes. Title/description are read-only by default (click Edit from overflow or pencil icon). This is the recommended approach because membership changes are the most frequent edit and should be zero-friction. Matches the Catalog redesign design doc's vision of "chips at top" with click-through to Project/Collection views.

Variant B (Separate Edit Form): Evolves the current model-detail-edit-form.js pattern. All editing happens in a dedicated form panel that replaces the summary card when activated. Chip-based tag editor with autocomplete replaces the current comma-separated text input. Collections and Projects get multi-select pickers with search. Better for bulk metadata changes where the user wants to see everything at once.
Frequent vs. Favorites. Per #1516: Only Frequent is shown — Favorites is removed from the top rail. The ⚡ Frequent toggle in the top bar serves as a manual override (per frequents-favorites-layer2-derivation-rules.md: operator can "Mark as frequent" or "Mark not frequent", overriding auto-derivation from ≥3 prints in the configurable window). The status pill area shows the current frequent score (⚡ Frequent · 5 in 90d) for at-a-glance context.
Projects entity scope. Per #1484 and projects-design.md: Projects are designed but not yet built in the sidecar. The mockup shows existing project memberships as purple chips with ✕ to remove, and a "+ Project" picker dropdown with search + create-new. Project status (active, backlog, planning, evaluating) is shown as a subtle suffix in the picker options. The picker queries GET /api/projects (future endpoint).
Archive toggle placement. The user chose "Along the topmost part of the card where there are 3D View, Download buttons." 📦 Archive and ⚡ Frequent are positioned as toggle buttons in the top action bar, between the entity badge and the 3D View button. When toggled active, they get a distinct border color and background tint. The Archive toggle also triggers a warning banner below the top bar (shown in the "Archived State" variant above). Both toggles use instant API calls — no form submission needed.

Issues considered in this mockup design:
#1489 catalog_visibility + default filter + Show-archived chip · #1516 Remove Favorites, only show Frequent · #1227 Advanced Actions card (moved to overflow menu shortcut) · #1484 Projects UI CRUD + project view · #1401 Multi-select updates from catalog view (chip UX enables fast multi-tag/collection changes) · #1479 Left-rail navigation (picker dropdowns reference project/collection hierarchy) · #1544 Revise Catalog top-of-page UI (top bar with Frequent/Archive toggles) · #1540 Copy image from Archive to Catalog item (media toolbar) · #1217 Filter section formatting (media filter chips match PH pattern) · #1111 Phase 8 UI polish (chip-based tag/collection editing replaces raw text)
Recommendation: Implement Variant A (hybrid inline editing) as the default experience. The always-interactive chips for tags/collections/projects provide zero-friction membership management — the #1 editing use case. Variant B's full form is still needed for bulk title/description/advanced-field editing and can be triggered from the overflow menu's "Edit Title & Description" item. Both variants share the same top-bar placement of Frequent and Archive toggles.

The edit form component (model-detail-edit-form.js) should evolve to use the chip-based tag editor and collection/project pickers shown in Variant B, replacing the current comma-separated text inputs. The inline chips in Variant A can call the same PATCH endpoint with individual tag/collection add/remove operations for immediate feedback without a form save cycle.
